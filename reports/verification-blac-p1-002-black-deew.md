## 3. Non-régression
- Lint, typecheck et 38 tests passent ; build OK avec une configuration VAPID valide.
- Le flux « commande non VIP » n'exige ni cookie ni numéro ; les prix sont ceux de la base (écart possible avec l'affichage client si l'arrondi diffère : le serveur utilise `Math.ceil`, `commandes/route.ts` l.106 et l.111).
- Le gate VIP n'utilise plus `sessionStorage` comme preuve d'accès ; les clients déjà connectés devront se reconnecter une fois pour obtenir le cookie.
## 4. Risques avant mise en ligne
1. **Rien n'est commité** : les correctifs n'existent que dans l'arbre de travail ; un déploiement depuis le dépôt ne les contiendrait pas.
2. **Migration non appliquée ni vérifiée** : `20261006120000_black_deew_vip_hardening.sql` n'a pas été exécutée ici (`allowSupabase=false`). Tant que les policies `*_all` (A3, A9) existent en base, mots de passe et jetons restent lisibles ; l'efficacité réelle de A1/A4 dépend aussi du secret de signature du cookie en production (variable à vérifier sur Vercel).
3. **Build local cassé** : `VAPID_PRIVATE_KEY` de `.env.local` est invalide (13 caractères). À vérifier aussi côté Vercel avant déploiement.
4. **Concurrence sur créneaux et stock** (A15 incomplet) : `booked` et le stock restent en lecture puis écriture ; surréservation possible sous charge. Une RPC atomique reste à écrire.
5. **Pas de transaction pour l'approbation VIP** (A12/A13) : retour arrière compensatoire seulement ; cas `partial` à traiter manuellement.
6. **Couverture de tests insuffisante** : aucun test pour `update-order-status` (A14), `vip-approve`, `vip-request` (A6), le panier (A16) ni la fixation des prix (A15) ; les tests existants utilisent un faux client Supabase en mémoire.
7. **Droits admin** : `requireAdmin` accepte tout administrateur actif, sans distinction de rôle ; vérifier que c'est voulu pour `update-order-status`.
8. **Mots de passe VIP encore en clair** (`vip_individual_passwords`, `requested_password`) et renvoyés à l'admin par `vip-approve` : le hachage (A3) n'entre pas dans ce lot.
9. **Non vérifié** : parcours complet en exécution réelle, détail des autres routes protégées (superadmin, upload-image, releve, etc.), différence d'arrondi prix client/serveur.
